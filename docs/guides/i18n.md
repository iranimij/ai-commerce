# Translations (`@aicommerce/i18n`)

Every word a person reads comes from a message catalog. English is the source and the fallback;
Persian (`fa`) is the second shipped locale and is right-to-left.

```ts
import { createTranslator, defineMessages, directionOf, negotiateLocale } from '@aicommerce/i18n'

const setup = defineMessages('setup', {
  title: 'Set up your shop',
  modules: '{count, plural, one {# module} other {# modules}} enabled',
})

const locale = negotiateLocale(request.headers.get('accept-language'), ['en', 'fa'])
const { t, dir } = createTranslator({
  locale,
  catalogs: [setup],
  translations: { fa: { 'setup.title': 'فروشگاه خود را راه‌اندازی کنید' } },
  onMissing: (key, locale) => console.warn(`No ${locale} text for ${key}`),
})
t('setup.modules', { count: 3 }) // "3 modules enabled"
```

Messages use ICU syntax (plural, select, number and date formats), through `intl-messageformat`.

## Rules that bite

- Keys are `namespace.key`. Two catalogs with the same namespace throw at start-up.
- An unknown key throws (`Unknown message key "x"`), so a typo fails a test instead of showing
  `setup.titel` to a customer.
- A translation that uses different `{arguments}` than the English message throws when the
  translator is created. A missing translation falls back to English and is reported once through
  `onMissing`.
- `directionOf(locale)` gives `rtl` for Persian, Arabic, Hebrew and the other right-to-left
  languages. Put it on `<html dir>` and on `UiProvider dir` (see [the design system](ui.md)); the
  components use logical properties only.
- `negotiateLocale` reads `Accept-Language` with its `q` weights and falls back to English.
- Components in `@aicommerce/ui` hold no text: every label is a prop that comes from `t`.
- The Persian strings have not been reviewed by a native speaker yet.
